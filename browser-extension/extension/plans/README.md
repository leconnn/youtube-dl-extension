# Animation improvement plans

Generated by the `improve-animations` skill's audit of
`browser-extension/extension/popup.css` and `popup.js` (the only animated
surface in this repo — a plain CSS/JS extension popup, no framework or
animation library). Stamped at commit `caf781bee`.

Every plan targets `browser-extension/extension/popup.js`/`popup.css`, the
canonical source. `browser-extension/extension-chromium/` never needs
touching — its `popup.js`/`popup.css`/`popup.html` are copied from
`browser-extension/extension/` at build time by
`browser-extension/installer/build-chromium.ps1`, so fixing the canonical
files fixes both the Firefox and Chromium builds.

## Recommended execution order

**001 first, always.** Plans 002, 004, and 005 all reference the
`--duration-base`, `--duration-slow`, and `--ease-out` tokens plan 001
introduces in `:root`. Running any of them before 001 means hardcoding
values that should be tokens, contradicting the plan's own text — if you
must run one standalone, add the specific token(s) it needs by hand first.

After 001, the rest have no dependencies on each other and can run in any
order or in parallel (each touches a distinct, non-overlapping region of
`popup.css`):

1. **001** — motion tokens (prerequisite for 002, 004, 005)
2. **002** — progress bar (HIGH severity, highest-frequency animation in the popup — do this next)
3. **003** — reduced motion (independent, no token dependency, quick)
4. **004** — settings/video-info crossfade (most visible missed opportunity)
5. **005** — theme icon crossfade (smallest, most polish-oriented)

## Dependencies between plans

- 002, 004, 005 → depend on 001's tokens (`--duration-base`, `--duration-slow`, `--ease-out`).
- 004 and 005 use the identical `@starting-style` + `transition-behavior: allow-discrete`
  pattern for animating a `display: none` toggle without JS. 005 explicitly
  cites 004 as its exemplar if there's ambiguity in applying the pattern.
- 003 is fully independent — no shared tokens, no shared rules with any other plan.
- No two plans edit the same line of `popup.css`; 001 explicitly excludes the
  `#progress-bar` rule (owned by 002) and the `.hidden` class (touched by
  neither 004 nor 005, which each add new scoped rules instead of modifying
  it, since `.hidden` is shared by out-of-scope elements like `#thumb` and
  `#progress-wrap`).

## Browser support note (relevant to 004 and 005)

Both use `@starting-style` and `transition-behavior: allow-discrete`
(baseline-supported in Chrome/Edge 117+, Firefox 129+). This project's
Firefox `manifest.json` already requires `strict_min_version: "140.0"`, well
past 129 — no legacy fallback is needed for either browser target.
